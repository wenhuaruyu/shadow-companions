# 第二阶段 PostgreSQL 验收

## 实施依据

用户已同意沿用CloudBase环境中现有PostgreSQL。服务使用pg连接池，事务内固定同一连接。创建依靠请求回执唯一约束和整笔回滚实现去重，加入通过房间行锁协调并发请求。读取状态使用只读可重复读事务保持玩家列表和版本一致。

## 准备与启动

安装项目依赖后，由数据库管理员审核并执行 `apps/server/src/v2/schema.sql`，在独立anxian Schema建表。Schema撤销PUBLIC默认访问。应用账号只授予该Schema的USAGE和三张表的SELECT、INSERT、UPDATE、DELETE权限。云端创建账号及授权需在用户确认后执行，凭证由用户配置。

环境变量见 `.env.example`。按控制台配置DB_HOST、DB_PORT、DB_USER、DB_PASSWORD、DB_NAME和PUBLIC_ORIGIN。TLS按控制台要求设置DB_SSL与可信DB_CA，不跳过证书验证。云端尚未执行建表或配置连接。

使用 `npm run start:v2 --workspace @anxian/server` 启动独立第二版服务。当前开放create、join、state和health，前端完整协议接入在后续联调。

## 自动验证

`npm test` 执行输入、HTTP错误边界与现有玩法回归。配置PG_TEST_URL指向专用测试数据库后，真实PostgreSQL测试验证并发创建重放、抢座、本人权限、过期加入、故障回滚和重新建立服务对象后的读取。测试只删除自身记录。

基础测试可独立执行，真实数据库用例在未配置PG_TEST_URL时跳过。现在可通过下述临时数据库命令自动完成本地数据库与进程级验收。云端验收仍待接入。

## 容量验收目标

20房间40个在线客户端，每人每秒一次状态查询约40请求每秒，另外计算心跳、操作和反应点击峰值。读取无变化不写库，连接池初始上限5，数据库连接在请求结束后复用。

上线前使用真实服务和数据库测40客户端混合负载，记录同步延迟、接口错误率、连接等待、数据库CPU及事务锁等待，并覆盖集中点击、重复提交和同房间并发占座。PRD指定网络条件下，状态变更两秒内可见，余额与结算错误为零。用例通过才能确认当前套餐容量。当前体验版QPS、连接上限和数据库可用配额尚需核实。

## 云端接入待决事项

再次检查配置页，当前共享实例仍无内网地址，外网开启按钮禁用。因此原生pg驱动尚无法使用该环境的实际连接信息。不能将本地测试通过记录为已部署。

腾讯云官方支持HTTP RPC调用数据库函数，一次函数调用可执行一个事务。若当前实例最终只能经网关访问，可将占座及去重事务封装成数据库函数，再由Node后端调用。该方式需要另行实现接入适配、函数内权限检查和云端重试验收，不能把BEGIN和COMMIT分成独立HTTP请求执行。官方RPC文档提示需注意网关的执行权限行为，敏感函数必须自行校验可信调用身份。

此接入调整先向用户解释原因并确认，随后实现。尚未在云端创建表、函数、账号或修改网络配置。

## HTTP RPC 接入实现与部署步骤

用户于2026年11月7日同意实现HTTP RPC。现在提供 `rpc.sql` 和 `rpc.js`，使用相同前端接口，在STORAGE_MODE=rpc时经CloudBase HTTP RPC访问数据库。直连模式仍用于本地数据库验收。

创建和加入调用public.anxian_room_enter，读取调用public.anxian_room_state。函数使用固定search_path和显式限定表名，表仍在私有anxian Schema内。每个SECURITY DEFINER入口都以IS DISTINCT FROM检查网关注入的service_role声明，缺失声明同样拒绝。底层快照函数采用SECURITY INVOKER且撤销PUBLIC执行权限。部署需确认CloudBase实际服务端凭证映射出的角色为service_role。

同一请求用事务级咨询锁串行处理，再通过房间行锁控制占座，所有写入在单次RPC事务内提交。函数返回本人状态的白名单字段。Node只向网关发送玩家凭证摘要。服务端网关凭证放在RPC_SERVICE_TOKEN环境变量，浏览器仍只拿到玩家自己的恢复凭证。网关异常统一转换为脱敏503，明确的业务异常恢复为对应接口错误。

本地验证使用HTTP测试网关转发到真实PostgreSQL，并模拟网关注入已验证角色。这验证了适配器、存储函数和事务行为，尚未验证腾讯云实际网关的身份映射和响应格式。测试增加RPC角色拒绝、并发请求重放、过期、本人权限和数据库触发器故障回滚。

部署顺序如下。

1. 审核并执行schema.sql建立游戏私有Schema和三张表。
2. 审核并执行rpc.sql，以事务安装两个公共入口及内部快照函数，必要时等待网关元数据刷新。
3. 在云托管服务中配置STORAGE_MODE=rpc、PUBLIC_ORIGIN、RPC_ENDPOINT和RPC_SERVICE_TOKEN。RPC_ENDPOINT使用该环境地址后的 /v1/rdb/rest/rpc，凭证须为经过验证的服务端身份。
4. 用匿名和普通用户调用确认被拒绝，再验证服务端创建、加入、重复请求及状态恢复。
5. 最后执行云端40客户端混合负载验收。

云端SQL、服务端凭证及部署尚未操作，第二阶段云端验收待上述步骤完成。

RPC最终回归结果为10项通过、0失败、0跳过，语法检查通过。测试文件串行执行以隔离数据库故障注入。当前40客户端容量测试仍走本地直连存储路径，RPC用例验证其正确性与权限行为，RPC云端容量未验收。
