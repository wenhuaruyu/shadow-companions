# 第一章武力小游戏规则修订稿

本稿根据《逃离搜查》手机小游戏开发规格及现有两地双人游戏规则整理，作为待确认的玩法方案。当前只修改规格，实施前需确认。本稿中的时长、地图规模及巡逻参数为初始调试值。

## 剧情定位

小游戏暂名《后巷转移》，发生在黄慕兰寓所第一地点的事件阶段。

开场文案为“后巷传来搜查的动静。你需要带着联络袋穿过街巷，在安全窗口关闭前抵达接应点。”

玩家控制本人对局角色完成转移。被发现以“前路受阻，退回掩护处”表现，不安排历史人物被捕、死亡或真实营救失败的分支。抵达终点仅代表本人的武力事件完成。第一地点是否通关，仍由之后双方共同投入判定。

角色由主游戏的本人座位资料传入，头像和名字沿用主游戏，不提供重新选人入口，不根据隐藏身份改变人物外观、地图、难度或奖励。最终角色名称随主游戏统一。

## 进入与共同流程

双方完成剧情已读后，各自从智力或武力事件中选择一种。每人每地点一次小游戏尝试，双方可以都选武力。武力事件的移动和得分独立处理，对方只能看到事件类型、进行中或已完成、最终奖励。

点击开始前显示规则和静态地图预览。素材、触控组件和后端准备完成后才建立尝试并开始计时。开始请求失败时允许原请求重试。

同一次尝试中的被发现、回到检查点和刷新恢复，不产生新尝试。已结算后不能重新开始刷奖励。

## 地图与移动

使用一张固定二维俯视地图，初始按12列、7行设计。地图包含起点、两个检查点、一个安全区，以及墙体、固定巡逻守卫和固定照射区域。

路线必须依次经过检查点一、检查点二，再抵达安全区。三个目标沿可通行路线布置，已到达的检查点清晰标记。不可绕过检查点直接完成。危险区域不得永久封死必经通道。地图需在时间限制内有可验证的通关路线。

沿用主游戏固定横屏画布。竖屏查看时保持横屏布局，方向变化不重置棋盘、位置或计时。以适配后的横屏手机尺寸检查道路、标记和按钮可读性。

采用格子步进，每次移动一格，按住方向键时初始每200毫秒移动一格。守卫和玩家使用相同格子坐标系。支持按住连续转向，不做斜向移动。松手、触控取消或页面进入后台时立即清除持续输入。操作区禁止浏览器手势干扰。

## 守卫、灯光与受阻

先设置两名守卫，按固定点位数组循环，每600毫秒移动一格。守卫当前位置及朝向可见，其所在格为危险格。守卫巡逻以本次尝试的有效经过时长推进，刷新后继续相同时序。

先设置两处固定灯光，用明确的矩形格子区域表示，不旋转、不追踪、不计算遮挡。灯光边界与实际判定格一致。

玩家与守卫在同格、与守卫发生迎面换格，或进入灯光危险格时判定受阻。每一步按固定顺序处理移动、危险检查、检查点和终点，危险检查先于到达奖励。

受阻后显示约600毫秒提示，随后回到最近已激活的检查点。尚未到达检查点时回起点。受阻提示期间不接受移动，有效时间继续消耗。守卫时序继续推进，已到达的最高检查点保留。检查点与重生格必须位于安全区，避免连续受阻循环。

受阻不扣除现有属性，也不额外扣除奖励。次数可用于测试调参，首版不纳入奖励公式。

## 时长与奖励

预览后显示3秒准备倒计时，准备时间不计入60秒有效游戏时长。60秒是首轮试玩参数，与智力事件时长对齐，后续根据手机试玩统一调整规则版本。

| 本次最高有效进度 | 武力奖励 |
| --- | --- |
| 未到达检查点一 | +0 |
| 到达检查点一 | +3 |
| 到达检查点二 | +6 |
| 依次经过两个检查点并抵达安全区 | +10，立即结束 |

奖励按最高进度取一档，三个节点不累加。受阻回退不抹除已获得的最高进度。仅以抵达终点判定完整完成，不使用最快时间、受阻次数、隐藏身份或随机数加减分。

到达安全区、有效时间耗尽或玩家确认放弃时结束尝试。超时和放弃都按已确认的最高进度结算，未达到首个检查点为0。结算界面显示到达位置、最终增加值和当前武力余额。

玩家初始武力仍为5。终点奖励到账后为15，后续共同任务的投入从该余额扣除。第一地点共同需求仍为智力5、武力5。本稿以0/3/6/10保持与智力事件相同的奖励上限，实际难度与收益是否均衡需试玩验证。

## 暂停、恢复与同伴等待

沿用全局暂停规则，页面后台或连接失联后，由服务端确认暂停，双方进行中的事件停止有效计时。纯横竖屏变化不触发暂停。

刷新恢复同一次尝试的地图版本、位置、检查点、有效经过时长和巡逻时序。双方恢复确认与120秒恢复窗口由主游戏统一处理。

全局暂停恢复目前尚待实现，属于本小游戏正式联网验收的前置依赖。开发原型时可先验证本地输入和固定地图，正式接入时补齐该依赖。

一人完成后显示“已完成，等待同伴”，不能再次移动或重玩。双方事件都结算后，共同进入投入阶段。

## 服务端裁决与奖励事务

客户端负责即时绘制和触控反馈。地图、碰撞顺序、守卫路线、移动间隔、检查点及奖励档位使用固定规则版本，客户端与服务端共用相同的确定性规则。

服务端保存尝试编号、有效计时锚点、位置、最高检查点和单调输入序号。客户端上报移动输入，服务端验证速度、顺序和路线，并计算有效进度。客户端声明的最终分数或抵达终点不能直接作为奖励依据。

联网同步频率、客户端预测纠正方式和允许的网络时间误差需通过原型实测后确定。现有云端延迟尚未达到既定目标，不能要求每个200毫秒步进等待一次HTTP往返。输入可批量同步，但服务端应限制可接受的时序与批次跨度，避免任意补报通关轨迹。

最终进度、奖励、属性增加、唯一奖励账本及请求回执在同一数据库事务提交。重复结算只返回原结果。提交响应丢失时沿用原编号重试。对方不可读取本人完整移动轨迹或隐藏指令。

## 开发范围与验收

首版使用简单图形、固定格子地图、固定路线和灯光。实现一次移动、受阻回退、检查点、准备倒计时、有效计时、放弃、恢复和一次性奖励。角色立绘与地图装饰可复用现有素材。

本期范围止于这些规则。追逐AI、寻路、动态灯光、随机地图、道具、技能、生命值、排行榜及双人共享同一迷宫均留待后续设计。

验收覆盖固定地图可通关、墙体阻挡、迎面换格危险、灯光边界、回退检查点、松手停止、后台输入清除、0/3/6/10四档奖励、刷新恢复、超时与终点同时发生、重复结算、响应丢失重试、旧规则对局恢复，以及手机上的流畅度和主剧情返回。

## 难度与取舍

固定格子地图、守卫数组巡逻和矩形灯区的本地原型属于中等开发难度，基础实现可采用Canvas或现有DOM组件，不必引入游戏引擎。相比当前点击反应初稿，需要增加地图、输入状态、碰撞与检查点逻辑。

联网计时、暂停恢复、位置持久化与服务端轨迹校验的开发和测试成本更高。建议先以同一规则完成本地可玩验证，再接入已有尝试与奖励事务，最后进行真实双机弱网验收。原有事务基础可复用，移动校验需要新增实现。
